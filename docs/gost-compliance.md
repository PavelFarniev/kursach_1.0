# Реализация требований и подготовка к отчёту

## Интерфейс и эргономика
- У интерфейса есть единые паттерны карточек, форм, статусов загрузки и ошибок.
- Для ключевых контролов добавлены явные подписи, а для опасных действий — подтверждение.
- Для части интерактивных элементов добавлены `aria-label`, `role="alert"` и `aria-live`.

## Контроль доступа
- Backend проверяет access-token, серверную сессию, активность пользователя и роль администратора.
- Admin-раздел защищён одновременно на frontend и backend.

## Журналирование и мониторинг
- Добавлен файловый аудит в `backend/runtime_logs/audit.log`.
- Логируются события авторизации, logout, AI-запросы, управление курсами и пользователями, операции с заметками и прогрессом.

## Криптографические меры
- Пароли хешируются через bcrypt.
- Refresh/reset токены хешируются.
- GigaChat-ключ пользователя шифруется перед сохранением.
- Основная аутентификация переведена на `HttpOnly` cookie.

## База данных
- В миграциях оформлены внешние ключи, уникальные ограничения, `CHECK`-ограничения.
- Добавлены trigger-ы на обновление `updated_at`.
- Для эксплуатации добавлены скрипты backup/restore.

## Тестирование
- Frontend-тесты добавлены через Vitest и Testing Library.
- Backend-тесты дополнены проверками cookie-аутентификации и времени ответа.

## Что остаётся сделать вручную
- Добавить скриншоты интерфейса, тестов и лог-файла в итоговый отчёт.
- При наличии доверенного CA для GigaChat вернуть `GIGACHAT_VERIFY_SSL_CERTS=true` и указать `GIGACHAT_CA_BUNDLE_FILE`.
